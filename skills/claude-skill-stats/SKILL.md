# claude-skill-stats

扫描 `~/.claude/projects` 下的会话日志（含子代理轨迹），统计三个渠道的调用——**模型调用**（模型发起的 Skill 工具调用）、**手动触发**（用户 /斜杠命令）、**MCP 调用**（`mcp__<server>__<tool>` 工具调用，只按 server 汇总）——并把结果渲染成数据内联的单文件 HTML 看板，双击即开、离线可用。

## 怎么跑

在本技能目录下执行：

```bash
node scripts/skill-stats.mjs
```

- 默认输出系统临时目录下的 `skill-stats.html`，可用 `--out <path>` 改（如 `--out D:/1vault/x/tools/skill-stats.html` 覆盖更新旧看板）。
- 数据源默认 `~/.claude/projects`，可用 `--projects-dir <dir>` 改。
- 脚本在 stdout 打印各渠道数量、合计、范围、输出路径——**直接把这些数字报告给用户**，不要自己再去解析日志。
- 全程只读取日志、只写一个 HTML 文件，无其他副作用；无需安装依赖（Node ≥ 20.12）。

## 跑失败时

| 症状 | 一线修复 | 仍失败兜底 |
|---|---|---|
| `node: command not found`，或报 `parentPath` 未定义 | `node --version` 检查；< 20.12 时告知用户升级 Node | 不要自行改写脚本迁就旧版本，也不要改用手工解析日志 |
| 打印「会话日志目录不存在」并退出 | 与用户确认本机会话日志实际位置 | 用 `--projects-dir <dir>` 重试；确认无日志就如实告知，不虚构数据 |
| 打印「未知参数」并退出 | 只支持 `--out` 与 `--projects-dir` 两个参数，检查拼写后重跑 | — |
| 跑通但合计为 0 条 | 检查 `--projects-dir` 是否指错目录 | 如实告知用户范围内无数据，不编造数字 |
| 其他报错 | 把报错原文展示给用户 | 绝不改用 grep 或手工解析日志兜底——那会违反口径红线 |

## 报告时的口径说明（主动说，别等用户质疑）

1. **跨项目统计**：扫描的是全部项目的会话，结果里出现其他仓库专属的 skill / server 是正常的，汇报时主动提一句。
2. **自计数**：正在生成快照的会话本身也会被计入（通常 ≤2 条），页脚已注明。
3. **数据范围**：`~/.claude/projects` 只保留近期会话，不是全量历史；页头有起止日期。
4. **子代理**：`subagents/` 下的子代理轨迹计入统计，与主会话同一去重规则。

## 🔴 CHECKPOINT · 口径红线（改前必须与用户确认）

脚本头部注释记录了完整口径，以下是不可擅自更改的部分——它们是踩坑后与用户逐条确认的结论：

- **逐行 `JSON.parse`，绝不用 grep 计数**。日志正文里会出现技能名、命令字样（包括统计会话自己的输出），grep 会自我污染、漏计参数序列化差异。
- 手动触发**只认以 `<command-message>` 开头的真实命令展开**，并剔除内置命令（clear / model / mcp / compact / handoff / init）。放宽这条会把正文里引用的 `/X`、`/xxx` 等占位文本误计进来。
- MCP 只按 server 汇总，**看板任何位置都不出现具体工具名**（用户明确选择）。
- 每条调用按 `tool_use.id` / 行 `uuid` 去重——轨迹可能被镜像到多个文件。

用户要求改口径（比如剔除子代理、改输出位置、加维度）时，先确认意图再改脚本，并同步更新页脚口径说明文字。

## 看板改版注意

- 单文件、零外部依赖、数据内联（`var DATA = [...]`），保持双击即开。
- 配色为三系列：`--s-model` 蓝 / `--s-slash` 橙 / `--s-mcp` 绿，各有深浅两套（CSS 变量 + `data-theme` + `prefers-color-scheme`）。改配色要两套模式一起改，并保证对各自背景的对比度 ≥ 3:1。
- 图表均为原生 DOM + CSS（无图表库）；明细表全部用 `textContent` 填充，数据经 `JSON.stringify` 注入时已转义 `<`，勿改回 `innerHTML` 直插数据。
