# 版本号规则

> 直接沿用用户飞马项目已上线的算法（`scripts/Publish-Release.ps1` 的 `Get-NextVersion` /
> `Test-VersionGreater` / `Get-OnlineVersion`），Node 版实现在 `scripts/engine/lib/version.mjs`。

## 格式

四段「**年.自增数.月.日**」，如 `26.11.10.14`：

| 段 | 含义 |
|---|---|
| 年 | 两位年号（2026 → `26`） |
| 自增数 | 同一自然年内**每次发布 +1**，跨年重置为 1 |
| 月 / 日 | 发布当天的月、日（不补零） |

排序语义是 **年 > 自增数 > 月 > 日**。因为自增数每次发布必增，新版本号**严格大于**上一版。

## 为什么不用 semver

因为这四段要直接当 Windows 可执行文件的 `VersionInfoVersion`（Inno 要求纯数字四段），
同时又要人能一眼看出「哪年发的、第几次、哪天」。`1.2.3-beta` 这类带后缀的版本号
塞进 `VersionInfoVersion` 前还得剥后缀，多一道容易忘的工序。

## 三源取大（「版本号以线上为准」）

基准取这三者的**严格最大**，再推下一版：

1. **线上清单里的 `version`** —— 权威来源；
2. **本地状态里记的上一版**（`release-state.json` 的 `versions.client`）；
3. **显式 `--base`** —— 离线或后端不通时的逃生口。

```bash
node scripts/engine/release-version.mjs --config release/release.config.json --print
# -> 26.11.10.14
```

**为什么必须读线上**：本地状态会落后 —— 换机器、上次发布失败、别人发过版。
只信本地就会发出**低于线上**的版本号，而客户端只认「版本更高」，**那一版等于白发**，
而且不会有任何报错。

**读不到线上又没给 `--base`** → 直接报错退出。不要用落后的本地号硬发。

## 比较必须按段比整数

```
26.10.1.1  >  26.9.1.1     ✓ 按整数比
26.10.1.1  <  26.9.1.1     ✗ 按字符串比（"1" < "9"）
```

比反的后果：客户端把新版判成旧版，**永远不更新**。

这条在两个地方都要小心：

- Node 侧：用 `compareVersions()`，不要用字符串比较，也不要用 `[version]` 之类的强转；
- **Pascal 侧**：用 `assets/inno/pascal-fragment.iss` 里的 `CompareVersions`（逐段 `StrToIntDef`）。

**校验一律用显式正则** `^\d+\.\d+\.\d+\.\d+$`：PowerShell 的 `[version]` 强转会接受 2~4 段，
挡不住三段号（`26.10.1` 会被当成合法版本，然后一路错下去）。

## 单调守卫（发版门禁）

`release-manifest.mjs` 在写清单前检查：

| 情况 | 处理 |
|---|---|
| 新版本 == 上一版 | **拒绝**。同版本重发客户端会认成「没更新」。要修内容就抬自增数 |
| 新版本 < 上一版 | **拒绝**。客户端只认「版本更高」 |
| 两者都要覆盖时 | `--allow-rewrite`（**仅限调试通道**） |

## 客户端回滚 = 前滚

客户端装出去的版本**收不回来**。所谓「回滚客户端」只能是：

> 用**旧代码**打一次**更高版本号**，重新走完整发版流程。

不要改小或回退版本号文件，也不要删已有标签 —— 客户端不会理会更低版本。

## 「本次是全量」不用独立状态文件

不要引入 `mode: full|payload` 之类的状态文件（早期版本试过，已废弃）。判据就是
**发版目录里在不在那份全量包**：打包时声明全量就把它收进去、没声明就清干净。
下一轮打包自动清掉它，于是「下一轮不会误推全量」是自动成立的，不需要任何复位动作。

这个做法把「两个真相」（状态文件 + 产物目录）压成了一个，避免了
「一个脚本按 full 发、另一个按 payload 发」这类静默发错包的事故。

## 每轮必须打 tag

阶段 9 打 `v<版本>` 标签（annotated）。**漏打的后果是下一轮的变更检测基准失效** ——
`git describe --tags --abbrev=0` 会退回到更早的标签，diff 出一大堆早该发布的改动。

标签指向**提交**而不是分支：先快进合并到 main，再在那个提交上打标签，
于是这一个标签在 main 和 dev 上都能看到。**不要去动已有的同名标签**
（重复打只会移动它，那是换提交，不是"分支也打上了"）。
